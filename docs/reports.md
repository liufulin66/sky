# 数据统计与Excel导出

已实现营业额、用户、订单、销量Top10及Excel导出五个接口。全部要求 `token: <管理员JWT>`，用户JWT不能访问。当前为单店模型，统计整个店铺，客户端userId不参与过滤。

## 请求与返回

| 方法和路径 | 成功data中的字段 |
| --- | --- |
| `GET /admin/report/turnoverStatistics` | dateList、turnoverList |
| `GET /admin/report/userStatistics` | dateList、newUserList、totalUserList |
| `GET /admin/report/ordersStatistics` | dateList、orderCountList、validOrderCountList、totalOrderCount、validOrderCount、orderCompletionRate |
| `GET /admin/report/top10` | nameList、numberList |
| `GET /admin/report/export` | 返回xlsx文件字节，不包装为Result JSON |

前四个图表接口均要求查询参数begin、end，格式为 `yyyy-MM-dd`，包含起止两个日期，最多366天。单日查询可以begin=end。日期颠倒、缺失、无法解析或超过范围时返回code=0及明确错误；JWT无效返回HTTP401。日期须处于MySQL DATETIME支持范围内，并能表示结束日次日零点；不支持1000年之前或9999-12-31及之后的日期。导出接口允许同时省略两个日期，默认范围见下文；只传一个日期仍然报错。

例如：

```text
GET /admin/report/turnoverStatistics?begin=2026-10-01&end=2026-10-03
```

日期按与工作台一致的北京时间日期解释。数据库查询范围为 `[begin当天零点, end次日零点)`，不会漏掉结束日的订单或包含下一天零点的数据。允许查询未来日期，没有数据的日期正常补零。

前四个图表接口沿用现有VO和页面契约，日期、每日数值、商品名称均使用英文逗号分隔的字符串，不改为JSON数组。日期按升序返回，每日数据与日期逐项对应。成功code=1，业务错误code=0；字段类型与已有返回对象一致。

## 营业额

按orders.order_time归属日期，只统计status=5已完成且pay_status=1已支付订单的amount。订单金额包含原订单中已经计入的打包费、配送费，不重新根据当前商品价格计算，也不连接明细后重复累加主表金额。

昨天提交、今天完成的订单归到昨天；未付款、未完成、已取消或已退款订单不计入营业额。零元有效订单可正常计入有效订单数量。

数据库使用DECIMAL求和，Java使用BigDecimal，以两位小数的普通数字字符串输出，不使用Double累计，也不限制整个统计区间营业额必须小于单笔订单金额上限。

```json
{"dateList":"2026-10-01,2026-10-02,2026-10-03","turnoverList":"10.10,0.00,20.20"}
```

## 用户统计

newUserList统计user.create_time落在每天范围内的首次注册人数，不是当天登录人数。

totalUserList表示截至该日结束时的累计注册人数，必须包含begin之前已有的用户。SQL以UNION ALL同时返回：

- 一条date=null的基数记录，数量为begin之前注册的用户数；
- 查询区间内按日期分组的新增人数。

Service从基数开始按日期累加；某天没有新增，新增值补0，累计值沿用前一天。基数和新增在同一SQL读取，不按每天分别查询，也不将整个历史期间的每日数据加载到Java。

例如begin之前已有10人，区间内每天新增2、0、3人：

```json
{"dateList":"2026-10-01,2026-10-02,2026-10-03","newUserList":"2,0,3","totalUserList":"12,12,15"}
```

本统计基于当前user表及注册时间；历史用户被物理删除后不能仅凭此表恢复删除前的注册总数。

## 订单统计

orderCountList包含当天下单的全部订单，包括待付款、已取消等；validOrderCountList只包含当天下单且已完成、已支付的订单。

totalOrderCount与validOrderCount为整个查询区间对应每日数量之和。整体完成率为 `区间有效订单总数 / 区间全部订单总数`，不是各日完成率的平均值。分母为0时返回0；其余按HALF_UP保留四位小数，返回0～1的小数，由页面乘100展示百分比。

统计按当前订单状态计算。订单以后完成或退款时，重新查询历史下单日期的数据可能变化；这与工作台口径一致，并非已冻结的财务日报。

每日数量使用Long聚合与输出；保留原VO中区间总数的Integer类型，超过该类型范围时返回明确业务错误，避免整数溢出。

## 销量Top10

统计查询区间内已完成、已支付订单的order_detail.number之和，按份数排名，不按订单行数、订单金额或成交单价排名。

- 按商品类型和商品id分组：菜品与套餐分开；同一商品不同口味合并；同名但id不同的商品分开。
- 套餐按售出的套餐份数统计，不拆成其中菜品份数。
- 只读取订单和订单明细，商品已经改名、停售或删除也保留成交记录；不连接当前商品表。
- 名称取区间内最近一条有效成交明细的快照，排序依据为下单时间降序、订单id降序、明细id降序。
- 排名按销量降序；销量相同按商品类型升序（菜品1、套餐2）、商品id升序，结果稳定，最多10项。
- 仅报表展示时把英文逗号替换为中文逗号，避免nameList拆分错位，不改写商品名或订单明细。历史名称为空时以“菜品#id”或“套餐#id”展示。同名不同商品仍可能显示相同标签，但销量独立。
- 历史异常明细中数量非正、商品id非正或菜品与套餐id不满足二选一的记录跳过。
- 无销量时nameList、numberList均为空字符串。

MySQL8窗口函数的工作方式：SUM(number) OVER按商品分组计算总份数；ROW_NUMBER() OVER按成交时间等给同组明细排序。最后只选每组序号1的记录，就能同时获得组内总销量和最近快照名称，再按销量取前10名。无需从Java加载所有销售明细。

## Excel导出

```text
GET /admin/report/export
GET /admin/report/export?begin=2026-10-01&end=2026-10-03
```

不传begin和end时，按北京时间导出最近30个完整自然日，不包含今天。例如北京时间2026-10-17请求时，范围为2026-09-17至2026-10-16。默认范围在一次请求中取一次当前日期；北京时间午夜切换后范围随之向后移动一天。此方式兼容现有管理端不带参数的导出请求。

自定义范围必须同时传入begin和end，包含起止日期，最多366天。范围校验与图表接口一致，无数据日期照常补零。

成功响应：

- Content-Type为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
- Content-Disposition为attachment，UTF-8文件名形如 `运营报表_2026-10-01_2026-10-03.xlsx`。
- 响应体是原始文件字节，包含Content-Length，并设置Cache-Control: no-store。

工作簿包含三个工作表：

| 工作表 | 内容 |
| --- | --- |
| 经营汇总 | 日期范围、营业额、订单总数、有效订单数、完成率、平均客单价、新增用户数、截至期末累计用户数及统计口径说明 |
| 每日明细 | 日期、营业额、订单总数、有效订单数、完成率、平均客单价、新增用户、累计用户 |
| 销量 Top10 | 排名、商品类型、商品ID、成交名称、销量份数 |

汇总数据来自同一批每日结构化数据，完成率按区间总数相除，客单价按区间营业额÷有效订单数计算，不平均每天的比率或客单价。区间新增用户数为每日新增之和，期末累计用户数为历史基数加区间新增。

Excel不拆分图表接口的CSV，而是复用底层日订单、用户和Top10三个Mapper查询。商品名称在独立单元格中保留原始英文逗号；商品ID以文本保存，防止Excel将长整数ID舍入。金额、数量、比率使用数值单元格，日期使用Excel日期单元格，金额格式保留两位小数，比率显示为百分比。没有销量时仍生成第三张表并显示暂无数据说明。

采用现有Apache POI的XSSFWorkbook在内存生成xlsx，不依赖磁盘模板或临时文件。ReportServiceImpl负责默认日期、查询与指标计算；ReportExcelWriter只负责布局、数值类型、样式、冻结表头、筛选及打印设置。样式每个工作簿只创建一次，关闭工作簿和内存输出流使用try-with-resources。

导出方法使用只读REPEATABLE_READ事务，三个查询读取同一InnoDB一致性快照。并发订单完成或新用户注册不会使本次导出的汇总、用户、Top10来自不同提交时刻。图表接口仍为各自独立请求，导出内容不保证与先前打开的页面处于同一时刻。

完整文件生成后才设置下载响应并返回；参数或生成失败时仍返回JSON业务错误，不附带文件下载头。前端已经使用responseType=blob，处理失败响应时应检查Content-Type，并解析JSON Blob，避免把错误信息保存成xlsx。导出为同步请求，沿用现有管理员鉴权，不保存服务端副本。

没有新增依赖、数据库字段或迁移SQL。已验证真实HTTP下载响应、中文文件名、POI重新打开工作簿、金额和百分比格式、日期补零、长ID和原名、空数据、默认范围及午夜切换、自定义单日和366天，以及并发提交期间的一致性快照。

## 实现与验证

统计调用链为ReportController → ReportServiceImpl → ReportMapper.xml，Excel渲染由ReportExcelWriter处理。未引入新依赖或Redis缓存，无新增数据库迁移。Top10使用MySQL8窗口函数，已通过本机MySQL集成验证。

营业额和订单报表共用一条按日订单聚合SQL；用户报表一条UNION ALL查询；Top10一条窗口函数查询。前四个接口每次调用只执行一条统计SQL，导出固定执行三条统计SQL，不随查询天数增加数据库往返次数。Java只对至多366个日期做补齐和输出组装。

测试覆盖四个接口鉴权、日期解析和校验、366天及单日边界、起止日零点、缺失日期补零、历史用户基数、整体完成率、支付状态过滤、零元有效订单、Top10数量及排名、口味合并、同名商品及类型隔离、改名快照、逗号展示、异常明细和空结果。MySQL测试仅操作随机前缀测试表。

集成测试启用参数：`-Dreport.mysql.tests=true`。
